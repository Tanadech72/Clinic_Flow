# วิธีวัดความถูกต้องของข้อมูล — Clinic Flow

ใช้วัดเกณฑ์ความสำเร็จข้อ 2 **"ความถูกต้องของข้อมูล ≥ 95%"**

## แนวคิด

เตรียมข้อมูลทดสอบที่รู้คำตอบล่วงหน้า บันทึกผ่านหน้าเว็บตามขั้นตอนการทำงานจริง แล้วดึงข้อมูลที่ระบบเก็บไว้จากฐานข้อมูลมาเทียบกับค่าที่ควรได้ทีละช่อง (field)

**ร้อยละความถูกต้อง** = (จำนวนช่องที่ถูกต้อง ÷ จำนวนช่องที่ตรวจทั้งหมด) × 100

**เกณฑ์:** ผ่านเมื่อ **≥ 95%**

## ขั้นตอน

### 1. เตรียมชุดข้อมูลทดสอบ (ก่อนบันทึก)

สร้างผู้ป่วยสมมติ **อย่างน้อย 10 ราย** แต่ละรายผ่านขั้นตอนครบ 1 รอบ (ลงทะเบียน → บันทึกก่อนตรวจ → ตรวจและสั่งยา → จ่ายยา) แล้วจดค่าที่ "ควรได้" ลงตาราง เช่น

| รายที่ | ชื่อ-นามสกุล | วันเกิด | ประวัติแพ้ยา | น้ำหนัก (กก.) | ส่วนสูง (ซม.) | ยาที่สั่ง × จำนวน | ราคา/หน่วย |
|---|---|---|---|---|---|---|---|
| 1 | ทดสอบ หนึ่ง | 1990-05-15 | Ibuprofen | 70 | 175 | พาราเซตามอล × 10 | 3.00 |
| 2 | ทดสอบ สอง | 1985-12-01 | - | 55 | 160 | ลอราทาดีน × 10, ORS × 2 | 5.00, 10.00 |
| … | | | | | | | |

ควรมีกรณีพิเศษปนอยู่ด้วย เช่น ผู้ป่วยที่ยังไม่ถึงวันเกิดของปีนี้ ผู้ป่วยไม่มีน้ำหนัก/ส่วนสูง และใบสั่งยาหลายรายการ

### 2. คำนวณค่าที่คาดหวังล่วงหน้า

| ค่าที่ระบบคำนวณเอง | วิธีคำนวณค่าที่ควรได้ |
|---|---|
| อายุ | ปีปัจจุบัน − ปีเกิด (ลบ 1 ถ้ายังไม่ถึงวันเกิดปีนี้) |
| BMI | น้ำหนัก ÷ (ส่วนสูงเป็นเมตร)² ปัดทศนิยม 1 ตำแหน่ง เช่น 70 ÷ 1.75² = 22.9 |
| สต๊อกหลังจ่ายยา | สต๊อกก่อนจ่าย − จำนวนที่จ่าย |
| ค่ายารวม | Σ (ราคาต่อหน่วย × จำนวน) |
| เลข HN | ไม่ซ้ำกัน และเรียงต่อจากเลขสูงสุดเดิม |

### 3. บันทึกข้อมูลผ่านหน้าเว็บ

บันทึกตามขั้นตอนการทำงานจริงทุกราย จดสต๊อกของยาแต่ละตัว**ก่อน**เริ่มบันทึก

### 4. ดึงข้อมูลที่ระบบเก็บไว้

รันคำสั่งนี้ใน MySQL Workbench (เปลี่ยน `'ทดสอบ%'` ให้ตรงกับชื่อที่ใช้ทดสอบ)

```sql
-- ข้อมูลผู้ป่วย การมาตรวจ และค่ายา
SELECT p.hn_code, p.first_name, p.last_name, p.date_of_birth, p.allergies,
       JSON_EXTRACT(v.vital_signs, '$.weight_kg') AS weight_kg,
       JSON_EXTRACT(v.vital_signs, '$.height_cm') AS height_cm,
       JSON_EXTRACT(v.vital_signs, '$.bmi')       AS bmi,
       mr.diagnosis, v.status, v.medicine_total
FROM patients p
JOIN clinic_visits v ON v.patient_id = p.id
LEFT JOIN medical_records mr ON mr.id = v.medical_record_id
WHERE p.first_name LIKE 'ทดสอบ%'
ORDER BY p.hn_code;

-- รายการยาที่จ่ายแต่ละครั้ง
SELECT p.hn_code, m.name, pr.quantity, pr.unit_price, pr.quantity * pr.unit_price AS line_total
FROM prescriptions pr
JOIN medical_records mr ON mr.id = pr.medical_record_id
JOIN patients p ON p.id = mr.patient_id
JOIN medicines m ON m.id = pr.medicine_id
WHERE p.first_name LIKE 'ทดสอบ%'
ORDER BY p.hn_code, m.name;

-- สต๊อกปัจจุบันของยาที่ใช้ทดสอบ
SELECT code, name, stock_quantity FROM medicines ORDER BY code;
```

อายุไม่ได้เก็บในฐานข้อมูล (คำนวณจากวันเกิด) ให้ตรวจจากหน้าข้อมูลผู้ป่วยแทน

### 5. เทียบทีละช่องและบันทึกผล

| รายที่ | ช่องที่ตรวจ | ค่าที่ควรได้ | ค่าที่ระบบเก็บ | ถูกต้อง (✅/❌) |
|---|---|---|---|---|
| 1 | ชื่อ-นามสกุล | ทดสอบ หนึ่ง | | |
| 1 | วันเกิด | 1990-05-15 | | |
| 1 | อายุ | 36 | | |
| 1 | ประวัติแพ้ยา | Ibuprofen | | |
| 1 | น้ำหนัก / ส่วนสูง | 70 / 175 | | |
| 1 | BMI | 22.9 | | |
| 1 | รายการยาและจำนวน | พาราเซตามอล × 10 | | |
| 1 | ราคาต่อหน่วยที่บันทึก | 3.00 | | |
| 1 | ค่ายารวม | 30.00 | | |

ผู้ป่วย 10 ราย × ประมาณ 11 ช่อง = ประมาณ 110 ช่อง ต้องถูกต้องอย่างน้อย 105 ช่อง จึงจะผ่านเกณฑ์ 95%

### 6. สรุปผล

| รายการ | จำนวน |
|---|---|
| ช่องที่ตรวจทั้งหมด | |
| ช่องที่ถูกต้อง | |
| **ร้อยละความถูกต้อง** | |

ถ้ามีช่องที่ไม่ถูกต้อง ให้ระบุสาเหตุในรายงาน เช่น กรอกผิดเอง (ไม่นับเป็นความผิดพลาดของระบบ แต่ควรบันทึกไว้) หรือระบบคำนวณผิด (ต้องแก้ไขแล้วทดสอบซ้ำ)
